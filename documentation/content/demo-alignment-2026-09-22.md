## Historical doubts raised

### 0.1
- Step 1 result table shows columns location, payment_cents and refund_cents, but the query only outputs location_id and revenue_cents. The result does not match the code.
- Step 3 refers to a model order_revenue that is never shown in this chapter.
- Step 3's diagram state has no content in this dump; confirm it renders.
- The chapter already flags that the first patch to add ref() is unconfirmed. The step 2 claim that ref() is 'not available in this package' at 0.1.1 is consistent with that but still unsourced.

### 0.2
- Step 2 schema.yml declares the relationship on orders (from order_id to payments). That tests that every order has a payment, which would not catch payment 2099. To catch the orphan payment the relationship belongs on payments, pointing to orders. The result panel says 'payments to orders', so the yaml and the result disagree.
- Step 1 places the query in the analyses folder, but the research says compiling analytical queries arrived in 0.2.3.0, not 0.2.0. Either present it as an ad hoc query or label the step 0.2.3.0.
- Accepted-values tests (0.2.3.0) are claimed in the feature list but not shown; minor.

### 0.3
- Temporary relations reducing unavailable time (a 0.3.0 claim) are not shown; acceptable as a side feature.
- Step 2's result is labelled 'prepared scheduling outcome', which correctly signals it is not a captured log.
- profiles.yml uses 'run-target' under a 'user' key here, while chapters 0.7 and 0.8 use 'target' and a named profile. Confirm which key names apply at each version.

### 0.4
- Step 3 shows order_revenue.sql without the incremental config from step 2. The visitor sees the config disappear. Step 3 should show the same configured model.
- Every model in steps 1 and 3 starts with a '-- Fixture phase:' comment. These are authoring notes, not period code, and should not be visible to visitors.
- sql_where with {{ this }} matches the 0.4.0 pattern; no doubt there.

### 0.5
- Placing vars under models: waffle_shop: vars: matches the 0.5.0 layout; no doubt there.
- The '.0' appended after var() in SQL is unusual but valid; it is a presentation choice, not a historical issue.
- 'Safer incremental writes' (0.5.0) is claimed but not shown or explained; acceptable as a side feature.

### 0.6
- Step 1 says the rule is 'typed out in several models' but only one query is shown; the claim is fine but the evidence is thin.
- Macro syntax and the macros folder match 0.6.0; no historical doubt.
- Hooks and target context are claimed but not shown; acceptable as side features.

- profiles.yml here uses 'target: dev' and dbt_project.yml uses a 'profile:' key, while chapter 0.3 uses 'run-target' under 'user'. Confirm when the rename happened and use period-correct keys in each chapter.
